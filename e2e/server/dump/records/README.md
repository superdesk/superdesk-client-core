# Can easily be ported to main snapshot:

* editor3-tables - adds tables formatting option to story content profile.
* custom-blocks - adds custom blocks to story/body_html content profile. Creates a new custom block vocabulary.
* compare-fields - adds urls/boolean/manual-entry-dropdown custom fields and a populated dateline to the Story profile, with two article versions carrying differing values. Used to exercise the compare-versions and print-preview field rendering.
* authoring-header - state the authoring header row needs and `main` lacks: `signal` plus `correction_sequence` on "test sports story", the legal/sms/not-for-publication flags plus `rewritten_by` on "story 2", a two item translation chain ("Header translations original" / "Header translations german"), "Broadcast of Story 5" (a broadcast item whose `broadcast.master_id` points at the published "Story 5", for the MASTER block), and two more items sharing the slugline "Story 3". "Story 3 sibling" makes "Story 3" show the Missing Link label; "Story 3 rewrite" has the same sibling but carries `rewrite_of`, so it covers the case where the rewrite link alone suppresses the label. The sibling is dated 2099 on purpose: Missing Link only counts related items created since midnight, snapshot dates are absolute and are never relativised at restore, so a future date is the only one that keeps matching as time passes.

# Must stay out of the main snapshot:

* media-items - `main` plus one item of every media type on the Sports desk working stage: "Rivendell picture" (picture), "Moria graphic" (graphic), "Isengard video" (video), "Lothlorien audio" (audio), and "Shire package", a plain package with no `highlight`, which `main` lacks because its only composite belongs to a highlight. Several specs assert exact item counts against `main`, so these items cannot be ported into it. Re-record it against a stack brought up with `SUPERDESK_URL=http://localhost:5000/api` (`e2e-up.sh` derives `SERVER_NAME` from that URL, and `e2e/server/settings.py` derives `MEDIA_PREFIX` from `SERVER_NAME`, so the backend stores the canonical prefix `http://localhost:5000/api/upload-raw`). On macOS, free port 5000 first: AirPlay Receiver answers there by default, which is why the everyday stack uses 5002. Rendition hrefs are absolute and are stored in the record, and `settings.py` only rewrites that one canonical prefix to whatever port the running instance answers on, so recording on any other port produces a snapshot whose thumbnails 404 everywhere but the instance it was recorded on. "Moria graphic" is a picture whose `type` was flipped to `graphic` directly in mongo and it keeps `profile: "picture"`, since no graphic content profile exists in the snapshot: it covers type filtering, not graphic authoring. The media was uploaded from `fixtures/` at the repo root: `metadata.jpg` (picture), `empty_metadata.jpg` (graphic), `metadata.mov` (video) and `audio.wav`, which exists only to give the audio item a source file.
